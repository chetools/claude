Sequential design of experiments

You can afford a fixed number of experiments to learn how a response depends on one or two inputs, and you want a model that predicts well everywhere. Experiments run in batches. After each batch a Gaussian-process model is refitted, and a strategy chooses where the next batch goes. Step through a session to see the model, its uncertainty, and why each point was chosen. Then compare the four strategies over many repetitions.

@@RS_TEST@@

Runs the same session (current sidebar inputs) in Rust (the WebAssembly behind the App) and in Python (sdl.run_session, in your browser) and compares them round by round. Both use the same algorithm and the same random numbers, so they should choose the same runs and agree to round-off. One exception is checked separately: when a fitted length scale ends on its bound, the likelihood is flat there, and round-off can move the two optimizers to different points of equal likelihood.

A race on identical work: K complete sessions (current sidebar inputs, seeds 1…K). Python first times three sessions with other seeds, then picks K so that its run takes about 10 seconds. Rust then runs the same K sessions on one thread, and again on all cores. Both run in your browser as WebAssembly. Python runs in a background worker, so the page stays responsive.

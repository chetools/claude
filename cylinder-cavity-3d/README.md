# Spinning, orbiting cylinder in a box: 3D vs 2D (lattice Boltzmann + finite volumes, WebGPU)

**Live page:** https://chetools.github.io/claude/cylinder-cavity-3d/

The 3D version of `cylinder-cavity-ns`. A cylinder spins about its axis and/or orbits the centre of a closed
square box, and the box is extruded along the cylinder axis (span L_z, periodic or closed by end walls). The
page runs a 3D simulation side by side with the 2D baseline (the same code with one spanwise cell, N_z = 1)
at identical inputs, to show through simulation where the flow becomes three-dimensional and how the 3D
flow differs from what a 2D simulation predicts.

- **Two independent solvers, cross-checked:**
  - *Lattice Boltzmann* (`python/lbm3d.py`): D3Q19, regularised collision (BGK and MRT optional), halfway
    bounce-back walls, Bouzidi interpolated bounce-back for the moving cylinder, momentum-exchange torque,
    refilling of uncovered nodes, global mass correction.
  - *Finite volumes* (`python/fv3d.py`): the 2D page's method in 3D — staggered (MAC) grid, MUSCL-minmod
    advection, Adams–Bashforth 2, projection with semi-coarsened multigrid, the cylinder as a penalisation
    mask (inner ramp).
- **Diagnostics** (`python/diagnostics.py`, fluid only): spanwise energy growth (E_w, E_3D and the energy
  per spanwise Fourier mode), the horizontal energy spectrum, and torque / energy / enstrophy histories.
- **Three implementations of each solver with the same names:** numpy reference (pytest), JavaScript
  float64 (CPU fallback) and WGSL compute shaders (WebGPU). The page's Validation section compares them with
  numpy values embedded at build time.
- **Renderers** (`web/render.js`, `render.wgsl`, `iso.wgsl`): slices, ray-marched volume rendering and
  marching-cubes isosurfaces of |ω|, ω_z, Q, speed or w.
- **Theory** (`web/theory_physics.md`, `web/theory_lbm.md`): vorticity and the Q-criterion, the 2D → 3D
  instability, Ekman layers, the finite-volume method, the lattice Boltzmann method (Chapman–Enskog,
  boundaries) and the diagnostics, derived step by step.
- **Step-by-step breakdown** (`python/walkthrough.py`) and an editable MoLab notebook
  (`notebook/walkthrough_molab.py`, generated by `python/make_molab.py`):
  [open in MoLab](https://molab.marimo.io/github/chetools/claude/blob/gh-pages/cylinder-cavity-3d/walkthrough_molab.py).
  Run all cells once after opening.

## Layout

```
python/
  SPEC.md                 shared interfaces (array layouts, names, seed, diagnostics, web runtime)
  lbm3d.py, fv3d.py       numpy reference solvers
  diagnostics.py          vorticity, Q, energies, spectra (fluid only)
  walkthrough.py          the breakdown cells; runner.py runs them; make_molab.py makes the notebook
  selftest_lbm.py, selftest_fv.py   numpy reference values for the page's self-test
  test_*.py               pytest
  ref2d/ns2d.py           copy of the 2D page's solver (Nz = 1 comparison)
  sweep/                  numba port of the LBM solver (parity ~1e-15) and the Reynolds-number sweep
web/
  lbm_cpu.js lbm_gpu.js lbm.wgsl   fv_cpu.js fv_gpu.js fv.wgsl   render.js render.wgsl iso.wgsl
  diagnostics.js app.js presets.json template.html base.css
  theory_physics.md theory_lbm.md code_guide.md
  tests/                  node and headless-browser tests
notes/
  verify/                 independent verification (REPORT.md, scripts, outputs)
  facts_for_theory.md     measured facts used by the theory text
build.py                  builds dist/cylinder-cavity-3d-standalone.html
```

## Build and test

Requirements: Node/npm, Python with `numpy scipy pygments markdown-it-py pytest marimo plotly` (and `numba`
for the sweep).

```bash
cd python && python -m pytest -q -m "not slow"     # reference checks
python build.py                                    # -> dist/cylinder-cavity-3d-standalone.html
python build.py --release --pages ../gh-pages-checkout/cylinder-cavity-3d   # strict build + publish
node web/tests/fv_cpu_test.mjs; node web/tests/lbm_cpu_test.mjs; node web/tests/diag_test.js
```

Page URL options: `?preset=<id>&N=…&Nz=…&field=…&mode=…`, `?cpu` (force the CPU solvers), `?selftest`
(run the Validation section on load), `?blit` (render through an offscreen texture, for headless browsers).

The page is one self-contained HTML file (Plotly, shaders, prerendered equations embedded); only the KaTeX
stylesheet loads from jsDelivr. The visual style follows `chetools/muse`'s `couette-standalone.html`.
